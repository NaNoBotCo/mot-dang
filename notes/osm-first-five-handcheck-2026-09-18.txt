THE GOOGLE PROBLEM — 10 records, all cm-newsletter-*. Each carries
attrs.maps = a goo.gl/maps or maps.app.goo.gl share link, geoPrecision
"exact", seven decimal places, and no pinVia. The coordinate was resolved
from the Google link. A coordinate read off Google Maps is Google's, and
putting one into OSM is the fastest way to have a changeset reverted and an
account marked. The NAME and the FACT THE PLACE EXISTS are not Google's —
those can go up — but the pin has to be found again some other way first.
  Affected: dream-star-academy-fc, faculty-fine-arts-cmu, graphic-heaven-hockey,
  kindred-studio, lecker-cafe-bistro, padel-club-cm, rong-sa-dang,

WHAT IT WOULD LOOK LIKE ON OSM
────────────────────────────────────────────────────────────────────────────
A single node, single changeset:

    shop        = massage
    massage:type = tok_sen
    opening_hours:signed = no
    note        = closes about 22:00 (observed 2026-09-04)
    source      = survey

  changeset:
    comment     = Add Phailin Tok Sen Massage, Chiang Mai old city (survey)
    source      = survey
    created_by  = manual edit

No import tag, no bulk, no script — one node, surveyed, which is the most
ordinary edit on OSM and needs no import review at all. That matters: it
starts the account with a normal edit rather than with a batch.

────────────────────────────────────────────────────────────────────────────
THE MECHANISM, STATED PLAINLY
────────────────────────────────────────────────────────────────────────────
OSM removed HTTP Basic auth from its API in 2024. Writing to it now needs an
OAuth 2.0 token, which a login alone does not give. Two ways in, both Nan's
hands:
  a) openstreetmap.org → logged in → the "Edit" tab → place the node in iD.
     One node, five minutes, and the edit is unambiguously hers.
  b) openstreetmap.org → My Settings → OAuth 2 applications → register one,
     scope write_api → then the upload can be run from here.
(b) is only worth it if more than a handful are ever going up.

────────────────────────────────────────────────────────────────────────────
WHAT THIS CHANGES UPSTREAM
────────────────────────────────────────────────────────────────────────────
1. The tier-A count of 52 is not a count of giveable records. Giveable, on
   today's reading, is 1. The gate needs a COORDINATE-provenance column, not
   just a record-provenance one — the same per-field work the DGA tier needs.
2. Every pin should carry pinUncertaintyM. 37 of the 52 carry no pinVia at
   all, which is the same silence the Google ten hid behind.
3. The Google ten are recoverable: their names, hours and phones are fine,
   and each one only needs a coordinate found another way.
