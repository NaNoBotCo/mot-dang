────────────────────────────────────────────────────────────────────────────
No — this has never been dug into.  notes/ holds 78 files and not one of them
is about arrival.  There is no SEO note, no distribution note, no referral
note, and no measurement of any kind anywhere in the repo.  Every claim below
about where readers come from is inference, including Nan's 99%, because the
site cannot currently count a single arrival.

Two corrections to the premise, both of which change the work:

1. A GOOGLE MAPS USER CANNOT ARRIVE FROM MAPS.  Maps is a closed loop; a
   result has no outbound link to a directory.  There are exactly three doors
   to that reader and none of them is inside Maps:
     (a) the WEB search that happens beside or before the map — "tok sen
         chiang mai" typed into Google, where web results sit under the pack.
         That door is an ANSWER page, not a place page.
     (b) the shop's own Google listing, whose website field the shop controls
         — reachable only through /claim.html, one shop at a time.
     (c) OSM.  Apple Maps, Organic Maps, Komoot, Garmin, Facebook's map and
         most model geo-knowledge read OpenStreetMap.  We read OSM and have
         never written a line back.  Fixing the substrate is the only way we
         reach a map-shaped reader at scale, and it is the one Google cannot
         close.

2. "AI FINDS IT" IS THREE DIFFERENT MECHANISMS and we are strong in the one
   that matters least:
     - PRETRAINING (llms.txt, llms-full.txt, an open dataset) — huge, slow,
       uncontrollable, and both files are live and good.
     - RETRIEVAL AT ANSWER TIME (the assistant runs a search and reads a
       page) — this is what decides whether ChatGPT names a Mot Dang shop
       tomorrow.  It rewards a page that answers the QUESTION, not one that
       names the PLACE.  We have 22 such pages.
     - TOOL USE (the assistant calls an API) — /api/v1 is written, frozen,
       schema'd, documented in api.js… and returns 404 in production.

    Wants: named shops with hours.

    walk-ins?"
    We hold 24 physio records as of yesterday.  No physio answer page,
    no hours in JSON-LD, no callable API.  ✗

S4  A developer asks an agent "what's open right now near me in Chiang Mai?"
    /open-now.html exists for a human.  The agent needs /api/v1 with
    near= and open_now=.  Written, frozen, 404.  ✗ — and this is the
    cheapest fix on the list.

S5  A shop owner googles their own shop name.
    Lands: their Mot Dang page — IF it cleared place_has_substance().  For
    ~10,400 places there is no page to find, so no claim, so no phone, so
    it never clears the bar.  ✗ a closed loop we built ourselves.

S6  A Bangkok Thai searches "ร้านนวดตอกเส้น เชียงใหม่" in Thai.
    Our pages are Thai-first and bilingual — this is our strongest hand and
    the one nobody else plays.  Blocked only by S1's missing answer page. ~

S7  Someone shares a place to LINE or Messenger.
    Every one of 24,059 places shows the same card.png.  A shared link that
    looks identical to every other shared link gets clicked less.  ✗

S8  An Apple Maps or Organic Maps user searches "massage" in the old city.
    They see OSM's 16 นวด elements for the whole province.  We hold 325 CM
    massage records and 30 tok-sen attributes and have never contributed
    one.  ✗ — and this is the only door to a map-shaped reader.

S9  A journalist or researcher wants "a Thai city directory dataset".
    llms-full.txt and places.json answer perfectly.  HF — the place they
    would actually look — 401.  ~

S10 An assistant needs to CITE us.
    A stable URL, a date, a count, a licence, a named method.  Every shelf
    page has all four.  This is quietly our best asset and nothing points
    at it.  ✓ but unadvertised.

S11 A reader arrives on a place page from anywhere and wants directions.
    Gets a bare coordinate pin in Google Maps.  ✗ cheap.

S12 A returning reader wants "what changed".  rss.xml exists.  ✓

    licence-compatible facts may go, never anything Google-derived.  Within
    that gate it is the highest-reach act available to this project.
G6  No arrival measurement.  Not a tracker — a first-party edge count of
    referrer host + landing path, no cookie, no third party, aggregated.
    Without it every line above stays a guess and stays unfalsifiable.
G7  HF dataset unpushed.
G8  Place og:images all identical; map links are bare coordinates.  Cheap.
