GITHUB RESOURCES THAT COULD IMPROVE MOT DANG — survey 2026-09-07
=================================================================

Question asked: does GitHub contain resources that could improve motdang?
Method: gh search over ~40 queries; direct look-ups of ~25 named repos;
then MEASURED the two that matter against data/canonical (25,914 records).
Everything below was run today; scripts + extract sit in cache/overture/.

-----------------------------------------------------------------
1. OVERTURE MAPS PLACES — the one that changes the numbers
-----------------------------------------------------------------
Repo: OvertureMaps/data (1,162 stars, MIT docs). Data: CDLA-Permissive 2.0
(attribution, no share-alike). Release 2026-08-19.0, public S3, no account.

It was parked on 2026-08-19 (notes/aggregators-and-tags-proposal) as
"GB-scale parquet, not stdlib — its own decision". That reason is gone:
python3 already has duckdb 1.4.5 on this Mac, and the whole Chiang Mai +
Chiang Rai extract took 33 seconds. Nothing was downloaded but the rows.

3. PyThaiNLP (1,152 stars, Apache 2.0) — TESTED, DOES NOT HELP THE ROMANISER
-----------------------------------------------------------------
1,500 random (nameTh, nameEn) pairs from data/canonical, letters-only compare:
   translit.py exact      344
   pythainlp royin exact  147
   either                 355
Ours is 2.3x closer to the signs. Royin never spaces (pratuthaphae), drops
clusters (สระ -> sa). Keep translit.py. PyThaiNLP's other parts
(newmm segmenter, Thai WordNet, spell) were not tested; the DP segmenter
from thapsap already does the cutting.

-----------------------------------------------------------------
4. SMALL, CHEAP, REAL
-----------------------------------------------------------------
- spicydog/thailand-province-district-subdistrict-zipcode-latitude-longitude
  (60 stars, MIT): one CSV, 334 CM+CR tambon rows with lat/lng to 3 decimals.
  geocode_local.py builds tambon centroids from our OWN pinned records and
  distrusts a tambon with few points; this is an independent witness for
  those. ~100 m precision, good enough for the tambon tier (±2,215 m).
- thailand-geography-data/thailand-geography-json (340 stars, MIT):
  7,436 subdistricts, TH+EN names + postcode + codes. No coordinates.
  Official EN spellings of every tambon/amphoe = a free alias table for the
  gazetteer's "Tha Phae/Thapae" class of miss.
- opening-hours/opening_hours.js (256 stars): the reference parser for OSM
  opening_hours strings, if refresh_hours.py (BOTS.md, to build) ever runs.

-----------------------------------------------------------------
5. LOOKED AT, NOT A FIT
-----------------------------------------------------------------
- Pagefind (5,445 stars): chunked static search, would cut the 9.5 MB
  index — but its own docs list Thai as "no segmentation" (only zh/ja/ko).
  A Thai query would not be cut into words. No.
- FlexSearch / MiniSearch / Orama: same class as searchcore.js; none ships
  a Thai tokenizer; the resolver decision (F2, 9/7) already moves ranking
  to the Worker + Vectorize. No gain.
- umami / plausible / goatcounter: page analytics, not query logging.
  F3 (log the search box) is a 20-line Worker write, not a product.
  cloudcounter (GoatCounter on CF Pages + D1) is the closest to the stack
  if page analytics are ever wanted.
- Thai address parsers (several, <10 stars each): weaker than the
  witness-based gazetteer built 9/7.
- Her own GitHub (NaNoBotCo, 39 repos): nothing motdang lacks. traffic-eye
  classifies user agents, not queries. thairoots/thapsap already ported.
